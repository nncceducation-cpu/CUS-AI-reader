# Code review of the 0.7.0 browser reader

Review of commit `8dc10e56` (browser reader 0.7.0), carried out while preparing
0.8.0. Every quantitative claim below was reproduced in a test; the assertions
live in `tests/browser_learning.test.mjs` and `tests/browser_model.test.mjs`,
and the statistical reference values were generated by
`scripts/verify_numerics.py` against statsmodels and scikit-learn.

Nothing in this review changes the standing conclusion of
`ACCURACY_AUDIT_2026-09-30.md`: there is still no validated diagnostic model
here, and none of the repairs below produce one.

## Summary

The partition, consent, abstention and classification-boundary design was
sound, and is kept unchanged. The defects fall into four groups: image
decoding that silently destroyed contrast or refused valid files, a promotion
gate whose arithmetic could not support the claim it made, a learner with too
little capacity and no safeguards to learn a focal lesion, and a label schema
that the project's own dataset could not populate.

## 1. Image decoding and preprocessing

### 1.1 NIfTI display windowing collapsed contrast

`decodeNifti` computed `rendered = min >= 0 && max <= 255` and, when true,
wrote the native voxel value straight into an 8-bit canvas:

- a volume with values 0 to 12 rendered across **12 of 255 levels**
- a float volume normalised to 0 to 0.3 rendered across **0.3 of 255 levels**,
  i.e. essentially black

The other branch divided by `Math.max(max - min, 1)`, which loses contrast
whenever the range is below 1: a volume spanning −0.5 to −0.25 rendered at
**25%** of available scale.

The supplied sample described in the accuracy audit (733 × 494 × 22, signed
16-bit, values 0 to 255) was **not** affected, because its range happens to
fill 0 to 255 exactly. Any conversion that normalises intensities — a common
step when producing NIfTI from DICOM — would have been.

0.8.0 windows on the 1st to 99th percentile, estimated from a deterministic
stride sample of the volume. All frames are still decoded; only the percentile
estimate is sampled. Constant volumes are flagged degenerate rather than
dividing by zero.

### 1.2 Two-dimensional-plus-time cines were rejected

`niftiData` rejected any 4-dimensional volume whose fourth dimension was not
1. A 2D-plus-time cine is stored with a singleton third axis and its frames on
the fourth, which is exactly the shape an ultrasound cine takes when converted
to NIfTI, so those files could not be opened at all.

0.8.0 resolves the frame count from `dim[4]` when `dim[3]` is singleton, labels
which axis was used in the technical audit, and still rejects volumes where
both axes are non-singleton as genuinely ambiguous.

### 1.3 Every frame was stretched to a square

`pixels()` scaled the source directly into a 64 × 64 canvas, discarding aspect
ratio. The supplied 733 × 494 geometry was compressed by a factor of **1.48**
in one axis. Two scanners with different frame shapes therefore presented
differently distorted anatomy for the same finding, adding a nuisance variable
that correlates with acquisition site.

0.8.0 letterboxes into the square, preserving source aspect to within 2%.

### 1.4 No sector isolation or annotation screening

The full frame, including vendor user interface and burned-in annotation, was
fed to the model. With a 64 × 64 globally averaged representation, scanner
furniture is a far stronger and more learnable signal than a germinal-matrix
haemorrhage, so a model fitted this way is at substantial risk of learning
acquisition site rather than pathology.

0.8.0 adds optional sector cropping, estimated once per source and recorded in
the audit, which declines to crop when the estimate would discard more than
three quarters of the frame. It also adds a saturated-pixel screen on the upper
band as a de-identification *aid* — it cannot read text or recognise a logo,
and is documented as such.

## 2. The promotion gate

### 2.1 The gate could be cleared by chance

Activation required 80% sensitivity and specificity per finding, at a fixed
0.50 threshold, with a documented minimum of two positive and two negative
holdout studies. At that minimum:

| Quantity | Value |
|---|---|
| 95% Wilson lower bound on a perfect 2-of-2 score | **34.2%** |
| Probability a coin-flip classifier clears 0.8 sensitivity *and* 0.8 specificity at 2 positive / 2 negative | **0.0625**, about 1 in 16 |
| Correct calls per class needed for a 0.80 Wilson lower bound | **16** |

So the gate's own stated threshold — 80% — was not supported by the evidence
the gate accepted. `BROWSER_LEARNING.md` already said "small-sample point
estimates are not adequate clinical evidence", but the software still called
the result a pass.

0.8.0 keeps the point-estimate check and adds a tier:

- **exploratory** — point estimates pass, the interval does not. Usable for
  workflow testing; requires an explicit acknowledgement before reading, and
  the weakest lower bound is quoted in the refusal text.
- **development-qualified** — every learned finding holds a 95% Wilson lower
  bound at or above 80% for both sensitivity and specificity.

Because the gate requires every finding to pass simultaneously, it is an
intersection of conditions and therefore conservative; no multiplicity
adjustment is applied, and the model card says so.

### 2.2 The replacement rule compared two point estimates

Replacing the active model required mean balanced accuracy at least 0.02
higher, with no uncertainty on the difference and no account of the fact that
serial scans from one infant are not independent.

0.8.0 adds an infant-clustered bootstrap on the difference (2,000 resamples of
whole infants) and requires the lower bound to exceed zero for a
development-qualified replacement. This implements item 5 of the accuracy
audit's own list of work needed.

### 2.3 No discrimination, calibration or operating-point selection

The gate reported only threshold-dependent counts at a fixed 0.50 cut on an
uncalibrated sigmoid. 0.8.0 adds ROC AUC (rank-based, midranks for ties) and
Brier score to every finding, and selects each operating point by Youden's J on
an inner tuning fold drawn from the training partition, grouped by infant. The
development holdout is never read during selection — doing so would invalidate
the only independent measurement available.

## 3. The learner

### 3.1 Capacity

| | 0.7.0 | 0.8.0 |
|---|---:|---:|
| Trainable parameters | 2,543 | 39,879 |
| Frame embedding | 16 | 96 |
| Study representation | 32 | 192 |
| Spatial pooling | global average only | average **and** maximum |
| Frame pooling | fixed mean and maximum | learned gated attention and maximum |

The decisive problem was not the parameter count but the pooling. 0.7.0 applied
`globalAveragePooling2d` to the whole frame, which averages a small bright
lesion into a 16-channel mean — close to the worst available summary for a
focal finding. 0.8.0 keeps spatial maximum pooling alongside the average, so a
localised response survives, and learns which frames matter instead of
averaging over a whole sweep in which the lesion may appear in two frames.

Parameter counts were computed symbolically in `scripts/verify_numerics.py`
and independently confirmed by instantiating the real model under Node; both
give 39,879.

### 3.2 No class weighting

Masked binary cross-entropy with no positive weighting means that for a finding
present in a small minority of studies, predicting "absent" everywhere is close
to optimal. That scores zero sensitivity, so the finding could never clear the
gate no matter how long it trained. 0.8.0 weights the positive term per finding
by the training negative-to-positive infant ratio, clipped to [0.25, 4].

### 3.3 No regularisation, augmentation or seed

There was no dropout, weight decay or augmentation, and weight initialisation
and study order were unseeded, so a version could not be reproduced from its
own record. 0.8.0 adds dropout 0.3, L2 1e-4, optional augmentation, and a
recorded seed that reproduces a fit to within 1e-6.

Horizontal mirroring is offered **only** for coronal studies, with the
hemisphere labels exchanged. In a parasagittal view the horizontal axis is
anterior-posterior, so a mirror would reverse anatomy without exchanging
hemispheres; applying it there would teach the model a false relationship.

### 3.4 Chained TensorFlow.js tensor methods

The forward pass used chained methods (`z.mean(0)`, `p.log()`). These are
registered by the full `tf.min.js` bundle, so the browser was fine, but the
coupling made the learning path untestable outside that one bundle. 0.8.0 uses
the functional API throughout, which is what allows the graph to be executed in
CI on the CPU backend.

## 4. The label schema could not represent the project's own dataset

This is the most consequential finding.

`categoryAnnotations` throws unless an expert-confirmed hemisphere is supplied
for any GMH-IVH category. The accuracy audit records that for the 268 supplied
files, "No separate table of hemisphere-specific grades, measurements or infant
identities was found in the recursive inventory."

The two statements together mean the 188 category-labelled studies could
contribute **no training target at all** through the category route: the only
labels the dataset carries are exactly the ones the schema refuses to accept
without information the dataset does not contain. The tool could not be taught
from the data it was built for.

0.8.0 appends seven side-agnostic heads (`any_gmh`, `any_ivh`,
`any_distension`, `any_focal`, `any_bright`, `any_inhomogeneous`, `any_cyst`)
after the original fifteen keys, which keep their identity and position. A new
`categoryAnnotationsAnySide` supplies side-agnostic targets only and never
produces a hemisphere key, so laterality is still never fabricated.
`deriveAnyLabels` fills an any-side head only when the hemispheres settle it —
either side positive makes it positive, both negative make it negative, one
unknown leaves it unknown — and `labelConflicts` refuses contradictory
annotations instead of silently resolving them.

`categoryAnnotations` itself is unchanged and still throws on unknown
laterality, so the 0.7.0 contract and its tests hold.

## 5. Build and deployment

The single-file edition pins the inline script's SHA-256 in its
Content-Security-Policy. Any edit to that script invalidates the hash, and the
browser then blocks the entire script with no user-visible failure beyond a
console message. 0.7.0 shipped no build script, so this hash had to be kept
correct by hand across a 52 kB inline bundle.

0.8.0 adds `scripts/build_single_file.mjs`, which wraps each module in its own
IIFE (so module-private names cannot collide), computes both the script and
style hashes, writes them into the policy, and then re-extracts and re-hashes
the assembled document to verify them. `tests/browser_learning.test.mjs`
rebuilds in-process and fails if the committed bundle is stale.

As a check on the method: rebuilding with `reader.css` unchanged reproduced
0.7.0's published style hash `'sha256-Swch7S731HvU/obNwjcEYJ+1zpOeW/iWlktyfnzksgA='`
exactly.

## 6. Interface and accessibility

- **The frame-sequence attestation was pre-ticked.** `$('axis').checked =
  current.axisVerified` set a human confirmation from the decoder's own
  inference, so the reader attested on the user's behalf to the one thing the
  decoder cannot establish. Both confirmations now start cleared on every
  decode, and the decoder's inference is shown as adjacent text.
- Every status message was styled `.success`, including progress messages and
  anything that was not an error. Now info, success and error are distinct, and
  focus moves to the message region on error.
- The tab strip was plain buttons with no `tablist`/`tab` roles or
  `aria-selected`. Now present and maintained on switch.
- Re-selecting the same backup file did not fire `onchange`, because the file
  input was never reset.
- `studyFingerprint` keyed on `record.id`, a UUID regenerated on restore, so a
  restored library produced a different fingerprint for identical data. It now
  keys on study code, infant, partition and sorted source hashes.

## What this review does not establish

No diagnostic accuracy was measured. No real case was decoded during this
review; the media assertions use synthetic NIfTI fixtures and synthetic
analysis buffers, and the learning assertions use synthetic noise. The
statistical and architectural claims are reproducible; the clinical ones remain
entirely outstanding and are listed in `VALIDATION_PROTOCOL.md` and section
"Work needed to establish accuracy" of the accuracy audit.
